# Stage 3: E2E Test Generation (Playwright)

**Purpose:** Generate Playwright E2E tests that verify the feature behaves correctly from the user's perspective. Think like a QA engineer — test behavior, not implementation.

---

## Playwright Config

If `{project-root}/playwright.config.ts` does not exist, create it:

```typescript
import { defineConfig, devices } from '@playwright/test'

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: 'html',
  use: {
    baseURL: 'http://localhost:8080',
    trace: 'on-first-retry',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  ],
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:8080',
    reuseExistingServer: true,
  },
})
```

Also ensure `e2e/` directory exists and add it to `.gitignore` exclusions if needed.

## Generate Tests

**Target file:** `{project-root}/e2e/{feature-name}.spec.ts`

If the file already exists, append new `test()` blocks — do not overwrite existing tests.

Write tests based on the approved plan from Stage 2. Each test must:
- Be self-contained (no shared state between tests)
- Use `data-testid` attributes for element selection (not CSS classes or text)
- Call `loginAs()` for authenticated flows
- Assert on visible outcomes, not internal state

**Test structure pattern:**

```typescript
import { test, expect } from '@playwright/test'
import { loginAs } from './helpers/auth'

test.describe('{Feature Name}', () => {
  test.beforeEach(async ({ page }) => {
    await loginAs(page, '{role}')
  })

  test('{scenario description}', async ({ page }) => {
    await page.goto('{route}')
    // actions
    // assertions
  })
})
```

**Coverage rules:**
- `smoke` — one test for the primary happy path only
- `standard` — happy path + role guard + key edge case
- `full` — all of the above + error states + boundary conditions

---

## data-testid Convention

If the implemented components don't have `data-testid` attributes on key interactive elements, note which elements need them. The tests should reference:
- `data-testid="{action}-btn"` for buttons
- `data-testid="{noun}-dialog"` for modals
- `data-testid="{noun}-status"` for status displays

Do not block test generation on missing testids — use accessible selectors as fallback and flag the missing attributes.
